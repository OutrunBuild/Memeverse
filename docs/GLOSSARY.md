# MemeverseV2 术语表

- **Verse**：一次 memecoin 启动实例，包含注册信息、生命周期状态和资金账本。
- **uniqueId / verseId**：verse 的唯一标识；注册中心生成，launcher 作为主键使用。
- **uAsset**：Genesis、preorder 与结算路径使用的资金 token；每个 verse 注册时确定，须在 RegistrationCenter.supportedUAssets 白名单内。
- **Memecoin**：每个 verse 的主代币，可由 launcher 按规则 mint。
- **POL (MemePol)**：流动性权益代币，代表与 memecoin 启动相关的权益与退出凭证。name/symbol 命名约定为 `POL-` + verse name/symbol（如 `POL-MEME`），见 [docs/spec/protocol.md](spec/protocol.md)。
- **Genesis**：募资阶段，允许 `genesis` 与 `preorder` 入金。
- **flashGenesis**：达到最小募资即允许提前结束 Genesis 并进入 Locked 的开关。
- **Refund**：募资失败后的退款阶段（终态）。
- **Locked**：募资成功后、流动性锁定阶段；允许领取初始 YT、加池 mint POL、分发 fee。
- **Unlocked**：当前实现中锁定结束后的退出阶段；需在 `unlockTime` 之后实际执行 `changeStage()` 才进入，赎回可用，但受保护公开 swap 要等该次迁移时间加上固定 `24 hours` 的 `UNLOCK_PROTECTION_WINDOW` 后才恢复。
- **post-unlock liquidity protection period**：unlock 后的受保护退出窗口；其目标是保证 POL / genesis liquidity 的赎回公平性，并为 POL Lend / PT-YT 语义提供统一结算窗口。
- **Preorder**：Genesis 内的额外 uAsset 池，进入 Locked 时结算为 memecoin 并线性解锁领取。
- **aggregate genesis funds**：成功部署资金口径，等于 `totalNormalFunds + totalLeveragedDebt`，不包含 preorder，并受 `type(uint128).max` 上限约束。
- **leveragedDebtFactor**：POLendUpgradeable 杠杆债务系数；上限为 `uint128.max * 1e18`，这是技术有效上限，不是经济最优值。
- **preorder settlement**：preorder 结算专用 swap 通道，走显式 `Launcher -> Hook.executePreorderSettlement(...)` 路径，固定 1% 总费。
- **launch fee window**：池初始化后的费用衰减窗口（默认从 5000 bps 衰减到 100 bps）。
- **LP token**：Hook 为每个池发行的流动性份额代币。
- **main pool LP / POL**：`memecoin/uAsset` 主池 LP token，也是 POL。
- **auxiliary LP**：三个辅助池 `POL/uAsset`、`PT/uAsset`、`PT/POL` 的 LP token；普通创世参与者在 `Unlocked` 后按份额领取。
- **executorRewardRate**：主池 `uAsset` 费中给执行者的比例（基数 10000）。
- **Governor**：DAO 治理与 treasury 合约，接收 uAsset 国库收入。
- **Yield Vault**：memecoin 收益池，接收并累计 memecoin 收益。
- **Governance Cycle Incentivizer**：治理周期奖励账本与分发模块。
- **YieldDispatcherUpgradeable**：跨链/本链收益路由器，把 token 分发到 Governor 或 Yield Vault；非合约 receiver 按 tokenType 分流：MEMECOIN → burn、UASSET → 可配置的 `protocolTreasury`（`initialize` 传入、`onlyOwner` 的 `setProtocolTreasury` 可改）。现为 UUPS 可升级合约（`ERC1967Proxy` + UUPS，`_authorizeUpgrade` 仅 owner）。
- **Governance Chain**：`omnichainIds[0]` 指定的治理主链。
- **Registration Center**：注册参数校验、symbol 占用与跨链注册分发中心。
- **Registrar**：把注册结果写入 launcher 的执行层（本地或异链接收）。
- **DAY（注册时间单位）**：注册中心当前实现中的常量单位为 180 秒，不等于自然日。
- **Protocol Fee Currency（协议费代币）**：控制协议费**如何收取（收在哪个腿）、而非是否收取**的代币注册表（`supportedProtocolFeeCurrencies`）。池中存在协议费代币时，协议费收在该代币上（两侧均注册时收输入侧）；池中无协议费代币时，协议费从输入侧直接收取（普通池，swap 正常成交、不回退）；解析式 `protocolFeeOnInput = inputSupported || !outputSupported`。详见 [docs/spec/swap/uniswap-v4.md §3](spec/swap/uniswap-v4.md)。
- **普通池 / ordinary pool**：protocol-fee 配置下输入与输出币种均未在 `supportedProtocolFeeCurrencies` 注册的池。此时 protocol fee 仍落在输入侧（`protocolFeeOnInput = true`，解析式见上一条），swap 正常成交、不回退。详见 [docs/spec/swap/uniswap-v4.md §3](spec/swap/uniswap-v4.md)。
- **Referrer（推荐人）**：普通 swap 的 `hookData` 前 20 字节 packed 携带的地址（caller 用 `abi.encodePacked(referrer)`；`abi.encode` 左 padding 会被 `SwapFacet::_decodeReferrer` 误读，禁用）。详见 [docs/spec/swap/uniswap-v4.md §3](spec/swap/uniswap-v4.md)。
- **Rebate（返佣）**：普通 swap 有 referrer 时，从 protocol fee 切给 referrer 的份额。`rebate = protocolFee × referrerRebateBps / PROTOCOL_FEE_SHARE_BPS`（`SwapFacet::_computeRebate`，两级向下取整）。in-kind（与该 swap 的 protocol fee currency 一致），不进 treasury、不经下游 uAsset / POLendUpgradeable 转换。守恒与偿付能力约束见 [docs/spec/invariants.md INV-20](spec/invariants.md)。
- **referrerRebateBps（返佣率）**：返佣占总 fee 的 bps（默认 `1000` = 10%，上限 `FeeMath.PROTOCOL_FEE_SHARE_BPS = 3500`）；hook `initialize` 写入默认值，owner 经 `MemeverseUniswapHookUpgradeable::setReferrerRebateBps` 修改。配置矩阵见 [docs/spec/verse/config-matrix.md §2](spec/verse/config-matrix.md)。
- **pendingRebate（未领返佣）**：hook（Router）上 per-referrer、per-currency 的未领返佣累积；swap 时入账（`SwapFacet::_settleProtocolFee`）、referrer 经 `claimRebate` pull 领取。守恒与偿付约束见 [docs/spec/invariants.md INV-20](spec/invariants.md)，运维语义见 [docs/operations.md §3.11](operations.md)。
- **account session（账户会话）`[代码已证]`**：普通公开 swap 仅允许 contract account、Safe、ERC-4337 account 或 EIP-7702 delegated EOA 开始 session。账户必须在同一不可 catch 的 external account frame 内依次直接调用 `Hook.beginAccountSession()`、任意单一经济账户的 Router、再由同一账户调用 `Hook.endAccountSession()`；任一步失败整帧回滚。`end` 的语义是主动让出 session：省略 `end` 不会让单账户交易失败（交易结束时 EIP-1153 transient storage 自动清零 `activePrincipal`），但若同一外层交易后续还有账户要 `beginAccountSession()`（如 bundler `handleOps([A, V])`），省略 `end` 会让后者回退 `AccountSessionAlreadyActive`；因此多账户串行场景 `end` 必须。传统 no-code EOA 不能开始 session；EIP-7702 delegated EOA 仅因 delegation code 的 `code.length` 非零被接受。该检查只用于拒绝传统 no-code EOA，不验证账户实现、签名或 allowlist。
- **session principal（会话主体）`[代码已证]`**：`Hook.beginAccountSession()` 捕获 `msg.sender` 作为 session 唯一 economic principal。它不是 Router、`hookData`、Universal Router `msgSender` 或 `tx.origin`；Hook 在本 transaction 的 transient state 中保存并在 callback context 中传递它，供普通动态费的 per-trader 状态使用。
- **diamond Router（MemeverseUniswapHookUpgradeable）**：Uniswap v4 hook 的单一外部地址与唯一 storage owner。UUPS 可升级 implementation（`ERC1967Proxy` + `UUPSUpgradeable`；implementation 持 `_authorizeUpgrade(...) => onlyOwner` 升级入口，授权由 Hook `owner()` 控制），布局 ERC-7201 namespace `outrun.storage.MemeverseUniswapHook`。保留 admin/view/liquidity/rebate-claim 直接实现 + 全部 modifier + 统一 `MemeverseUniswapHookStorage` struct，callback/fee/settlement entry 经 delegatecall 分发到 3 个 facet（1:1 签名细入口用 `_forwardCalldata` 做 selector 置换 + calldata 转发，非 1:1 签名入口如 `quoteSwapFeeWithContext` 仍用 `_facetDelegatecall` + `abi.encodeCall`）。外部观测所有 entry 都在 hook proxy 地址（统一 ABI）。owner 经 Hook `owner()` 直接 `upgradeToAndCall` 升级 Router 字节码、经 `setFacet` 替换 facet。详见 [docs/ARCHITECTURE.md §1.3](ARCHITECTURE.md) 与 [docs/spec/upgradeability.md](spec/upgradeability.md)。
- **facet（钻石分面）**：diamond Router 经 DELEGATECALL 调度的逻辑合约（SwapFacet/DynamicFeeFacet/SettlementFacet），承载 v4 callback / 动态费率 / preorder settlement 主体。本身无独立 storage、无 `Initializable`、constructor 绑定 poolManager immutable（须传与 hook 同一个；immutable 为字节码级，不占 storage slot），与 Router 绑同一 ERC-7201 slot `outrun.storage.MemeverseUniswapHook`（经 `layout at`），在 hook proxy storage 上下文执行（`address(this)` == hook proxy）。防直接调用靠运行时守卫 `onlyViaRouter`：facet 部署时把自身地址烤入 `__self` immutable（字节码级，不占 storage slot），每个 logic 函数检查 `address(this) != __self`；经 Router DELEGATECALL 时 `address(this)` = hook proxy ≠ `__self` 通过，直接 CALL 时 `address(this)` = facet == `__self` revert（不依赖 storage 读）。owner 经 `setFacet(bytes32 role, address)` 按 role（`SWAP_FACET_ROLE`/`DYNAMIC_FEE_FACET_ROLE`/`SETTLEMENT_FACET_ROLE`）替换。与 delegatecall sibling 形似而本质不同：facet 共享 hook namespace + 显式运行时守卫；sibling 共享 launcher namespace + 运行时守卫由继承 `DelegatecallOnly` 提供（而非靠构造副作用）。详见 [docs/ARCHITECTURE.md §1.3](ARCHITECTURE.md)、[docs/spec/upgradeability.md](spec/upgradeability.md)。
- **delegatecall sibling（兄弟合约）**：MemeverseLauncherUpgradeable 为缩减 facade 字节码而抽出的 delegatecall-only 逻辑合约，按业务边界拆为三大 sibling：`MemeverseLaunchImpl`（launch 生命周期）、`MemeverseSettlementImpl`（settlement / claim / fee 链）、`MemeverseLiquidityImpl`（bootstrap 流动性 / POL mint / LP 赎回）。与 facade 共享 ERC-7201 namespace `outrun.storage.MemeverseLauncher`，在 proxy 存储上下文执行；owner 经 `setLaunchImpl` / `setSettlementImpl` / `setLiquidityImpl` 替换。三大 sibling 均继承 `DelegatecallOnly`，EOA 直调 revert `DelegatecallOnlyCall`。详见 [docs/spec/upgradeability.md](spec/upgradeability.md)。
- **GenesisCredit**：与某个 18-dec `uAsset` raw-unit 1:1 对应的 ERC20+OFT 凭证（per-uAsset，由 `GenesisCreditFactory.deployCredit` CREATE3 部署，本链确定性地址（跨链同址需 factory+uAsset 均跨链同址，非合约保证））。credit path 只支持 `uAsset.decimals() == 18`：`1e18` raw uAsset 利息 : `1e18` raw GenesisCredit 抵扣。用户在 `leveragedGenesisWithCredit` 中把它 transfer 给 `POLendUpgradeable` 抵扣杠杆利息。符号约定为 `cr` + uAsset symbol（如 `crUUSD`）。`finalizeLeveragedGenesis` 会按该 verse `market.totalCreditInterest` burn 托管的 GenesisCredit；`Refund` 终态退回 GenesisCredit token。详见 [docs/spec/polend/genesis.md §4.1](spec/polend/genesis.md)。
- **leveragedInterestPaid（存储字段，承载 real 部分）**：用户级杠杆利息的真付 `uAsset` 利息分栏（`leveragedGenesis` 路径累计，与代码 `src/polend/POLendUpgradeable.sol::leveragedInterestPaid` 一致）。与 `creditInterestPaid` 物理隔离、独立累加；finalize 时 `realInterest = totalLeveragedInterest - totalCreditInterest` 全额清扫至 protocolTreasury；对外 view `totalInterestPaid(verseId, user)` 返回 real+credit 合计。会计不变量见 [docs/spec/invariants.md INV-21](spec/invariants.md)。
- **creditInterestPaid**：用户级杠杆利息的 GenesisCredit 抵扣分栏（`leveragedGenesisWithCredit` 路径累计）。与 `leveragedInterestPaid` 物理隔离、独立累加，不产生该 verse `uAsset` token 流入；market 级合计 `market.totalCreditInterest` 是 finalize burn 量的唯一权威。会计不变量见 [docs/spec/invariants.md INV-21](spec/invariants.md)。
- **home 链（GenesisCredit）**：GenesisCredit 的 merkle claim 单点写入链（Ethereum 主网）。GenesisCredit 的 `claim(...)` 是 permissionless merkle claim，但 merkle root 单点写入 home 链的 GenesisCredit（仅该实例 owner 可调 `setMerkleRoot`，可多次调用以轮换/修正/清空；远程链实例在运维纪律下 `merkleRoot` 保持 `bytes32(0)`（远程实例 owner 同样持有 `setMerkleRoot` 写入权限，代码不禁止））；非 home 链调用 `claim` 直接 revert。这是防止跨链重复领取的安全设计——同一份 credit 凭证只能从 home 链领出一次，再经 OFT 桥到目标链 redeem。运维语义见 [docs/operations.md](operations.md) GenesisCredit 节。
- **YT Flash Swap `[代码已证]`**：无独立 YT AMM 的 POL↔YT 兑换。复用既有 PT/POL Uniswap v4 池的流动性，先在该池做一次普通 PT/POL swap 取得或交付精确 PT，再在同一原子交易用 POLSplitterUpgradeable 的 split/merge 把 POL 与 YT 互换并清偿 AMM 债务。只提供两个用户入口：`swapPOLForExactYT`（POL→精确 YT）与 `swapExactYTForPOL`（精确 YT→POL）。不提供 Permit2、quote 入参、求根、Lens 查询、退款循环或管理员。canonical home：[docs/spec/swap/yt-flash-swap.md](spec/swap/yt-flash-swap.md)。
- **MemeverseYTFlashSwapRouter `[代码已证]`**：承载 YT Flash Swap 的独立 Router，与 `MemeverseSwapRouter` 相互独立。是 PoolManager 的正常 swap 调用者，底层 PT/POL 腿与普通 swap 走同一条 v4 + Hook 路径，复用既有 fee/referral/account-session；immutable 绑定 PoolManager / Hook / POLSplitterUpgradeable。两个用户入口 permissionless，但任何资金动作前要求 `hook.activeAccountSessionPrincipal() == msg.sender` 且 canonical dependency 与 Router immutable 一致。详见 [docs/spec/swap/yt-flash-swap.md §2–§3](spec/swap/yt-flash-swap.md)。
- **polInUsed / polOut `[代码已证]`**：YT Flash Swap 的实际结算依据（非历史 quote）。买入：先做 exact-input `y PT -> R_actual POL`，只从 payer 拉取 `polInUsed`（spec §4/§8 推导符号记作 `actualPOLIn = y - R_actual`）（要求 `0 < R_actual < y`，`polInUsed <= maxPOLIn`），不预拉 `maxPOLIn`。卖出：先做 exact-output `Q_actual POL -> y PT`，输出 `polOut = y - Q_actual`（要求 `0 < Q_actual < y`，`polOut >= minPOLOut`）。真实 `BalanceDelta` 是唯一结算依据。详见 [docs/spec/swap/yt-flash-swap.md §4、§8–§9](spec/swap/yt-flash-swap.md)。
- **flash split/merge baseline `[代码已证]`**：YT Flash Swap 的资金安全边界。用户入口在本地保存 Router 的 PT/YT/POL `RouterBalances` baseline，`PoolManager.unlock` 返回后必须确认三者精确恢复——预存 dust 不可消费（正常部署后 baseline 应为零），`recipient` 为 Router 被禁止。买入还需保证 split 后 Router→Splitter 的 POL 临时 allowance 归零。结算不变量见 [docs/spec/invariants.md INV-24](spec/invariants.md)。
